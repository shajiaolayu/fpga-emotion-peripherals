# 私有推理核心接口

外围与私有核心通过模块 `inference_core` 连接。此处描述集成契约，不包含网络结构、实现或权重。

| 端口 | 方向 | 位宽 | 契约 |
| --- | --- | --- | --- |
| `clk` | 输入 | 1 | 核心与加载器使用同一上升沿时钟 |
| `rst_n` | 输入 | 1 | 低有效；外围使用同步后的本地复位 |
| `load_en` | 输入 | 1 | 高电平的时钟沿写入一个像素 |
| `load_addr` | 输入 | 12 | 行优先地址 0…2303，每帧完整加载 2304 字节 |
| `load_data` | 输入 | 8 | 无符号灰度 0…255，外围不执行减 128；数值中心化由私有核心负责 |
| `start` | 输入 | 1 | 完成整帧加载后单周期启动，与 `load_en` 分开 |
| `busy` | 输出 | 1 | 运算期间有效；外围不在忙碌时启动或加载下一帧 |
| `done` | 输出 | 1 | 结果可用时产生单周期脉冲 |
| `scores` | 输出 | 224 | 七个有符号 int32，类别 i 对应 `scores[i*32 +: 32]` |
| `prediction` | 输出 | 3 | 有效类别为 0…6，与当前七路分数对应 |

类别次序沿用板级显示约定：0 平静、1 高兴、2 惊讶、3 悲伤、4 愤怒、5 厌恶、6 恐惧。百分比是显示端对分数的归一化，不是识别准确率。

现有集成还保留参数 `SIM_MAC` 及调试输出 `trace_valid`（1）、`trace_op`（6）、`trace_addr`（17）、`trace_value`（32）。外围生产通路不依赖这些调试数据；公开的仿真替身将其置零。

## 帧与结果所有权

1. 采集端仅发布通过完整性检查的帧；ROI 输出 48×48 灰度图。
2. 加载器按地址顺序发送 2304 字节，同时写入对应缩略图。
3. `start` 后等待 `done`，期间保留所选照片的缓冲区。
4. 显示端完成百分比、类别与计时元数据后提出发布请求，在消隐边界统一更新显示缓冲区。
5. 显示确认通过时钟域同步返回后，调度器才释放该次照片/结果的所有权。

`done` 时应同时提供稳定的七路分数与类别；外围在接收事件时锁存数据。复位会取消当前事务。测试替身的固定短延迟仅用于验证这一协议，不能用于推断真实核心速度。

## 测试替身的使用边界

仅独立集成仿真显式定义 `PUBLIC_PERIPHERAL_TEST` 并编入 `sim/inference_core_interface_stub.sv`。没有该定义，或定义了 `SYNTHESIS` 时，替身会引用故意不存在的保护模块并导致编译失败。真实硬件工程应排除整个 `sim` 目录并接入私有核心。
